## 1. What this project is

A Windows desktop app that generates professional PDF demand letters for Tier 2
pension contributions, matching the QFT (Qlac Financial Trust) sample layout.

- **Stack:** Java 21, JavaFX 21, Apache PDFBox, Maven (shade fat-JAR),
  WiX/jpackage MSI installer, Microsoft Publisher COM automation via embedded
  PowerShell scripts.
- **Input:** form values (letter date, contribution month/year, amount GHS,
  payment deadline) + an optional Microsoft Publisher `.pub` letter template.
- **Output:** an exact-preview PDF, saved where the user chooses. If no `.pub`
  is selected, a built-in PDFBox layout is used.

## 2. Hard invariants — never break these

1. **Stamped values are never shrunk.** If a value is wider than its
   placeholder, later text on the line shifts or word gaps tighten (the
   reflow post-pass in `ContentStreamEditor`). Values must not visibly overlap.
2. **Never modify the original `.pub`.** The tokenizer works on a copy; the
   converter opens a copy. The app never closes a Publisher instance it did not
   start.
3. **The installed app requires no Java** (jpackage bundles the runtime).
4. **Main window fits the desktop work area** (screen minus taskbar); the
   preview window opens at one fixed, centered size on every open.
5. **Preview is the exact bytes saved** — save-from-preview writes the PDF that
   was rendered.
6. **Version every change set** (user's explicit standing instruction:
   "whenever I implement changes, make it versions and also add documentation to
   the changes and features"). Bump `pom.xml`; the MSI script reads it
   automatically. MAJOR = output/workflow rework, MINOR = new feature,
   PATCH = fix/documentation. Add a dated section to `CHANGELOG.md`, update
   `README.md`, rebuild/reinstall, commit and push.

## 4. Architecture map — where to make changes

```
src/main/java/com/qft/demandnotice/
├── Launcher.java                  # fat-JAR entry point
├── Main.java                      # JavaFX app; main stage sized to Screen visual bounds
├── model/DemandNoticeData.java    # immutable notice data
├── service/
│   ├── DateFormatter.java         # "24th September, 2026"
│   ├── AmountFormatter.java       # "GHS 1,389.00"
│   ├── PdfGenerator.java          # built-in PDFBox layout (fallback without .pub)
│   ├── PubToPdfConverter.java     # .pub -> PDF via Publisher COM (PowerShell)
│   ├── PubToPdfTokenizer.java     # inserts tokens into a COPY of a filled-in .pub
│   ├── TemplateCache.java         # disk cache of converted PDFs (SHA-256 of .pub bytes)
│   ├── ContentStreamEditor.java   # token removal + overlap-free line reflow
│   └── TemplateStamper.java       # stamping pipeline + cache-first prepare(Path)
├── ui/MainController.java         # form, Browse, drag/drop, prefetch, status, preview orchestration
├── ui/PdfPreviewController.java   # rendering, paging, fit zoom, gesture zoom/pan, save
└── util/Constants.java            # ALL fixed text + layout constants (edit only here)
src/main/resources/
├── assets/qft_logo.png
├── scripts/pub_to_pdf.ps1, scripts/tokenize_pub.ps1
├── com/qft/demandnotice/ui/MainView.fxml, PdfPreviewView.fxml
└── styles.css
build/setup/                       # MSI script + icon assets; reads pom version
```

**Pipeline:** select/drop `.pub` → background prefetch (`TemplateStamper.prepare`,
single queue) → `TemplateCache` lookup by SHA-256 → on miss: tokenize copy
(`PubToPdfTokenizer`) + Publisher COM convert (`PubToPdfConverter`) → stamp
`{{LETTER_DATE}}`, `{{PERIOD}}`, `{{AMOUNT}}`, `{{DEADLINE}}` at full size with
reflow (`TemplateStamper` + `ContentStreamEditor`) → PDF bytes → preview → save.
Preview awaits the same preparation future; a failed conversion is retried on
the next click. Cold prepare ~28 s, warm ~2 s (including JVM startup); stamping
~250 ms, rendering ~950 ms. Publisher modal dialogs wait up to 4 minutes.

## 5. Session memory — where work ended

### Objective
Ship and maintain overlap-free stamped letters, a fast preview workflow, a
desktop-fitting UI, versioned releases with documented changes.

### Requirements and design decisions made earlier
- Reflow, never shrink: later runs shift or value-adjacent gaps tighten;
  no value font reduction. Verified against 24 value/template cases.
- Disk cache keyed by SHA-256 of `.pub` bytes (content-based invalidation,
  silent fallback on any cache problem).
- Template conversion prefetch starts as soon as a template is selected;
  one background queue; preview awaits that same future.
- Drag-and-drop reuses `MainController.adoptTemplate(Path)` so Browse and drop
  behave identically. Non-`.pub` drops are rejected with a status message.
- Gesture zoom: `Ctrl + ScrollEvent` handles wheel **and** Windows touchpad
  pinch (the OS reports pinch as ctrl+wheel); JavaFX `ZoomEvent` handles
  touchscreen pinch. Zoom is anchored at cursor/fingers; the ScrollPane remains
  pannable and `pannable="true"` gives drag-to-pan.
